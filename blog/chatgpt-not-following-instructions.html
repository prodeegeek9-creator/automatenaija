ChatGPT Not Following Instructions: Debug Playbook

A short, practical playbook to restore ChatGPT output quality using prompt tweaks, account and cache checks, and tool-specific fixes for n8n, Make.com and Zapier.

By the Automate Naija team·18 November 2026·6 min read

If you see chatgpt not following instructions, this compact playbook gets you from symptom to root cause fast: verify system and developer messages, try the same instruction placed in different message roles, check account and shared limits, clear conversation cache or regenerate, and fall back to another model to restore quality.

Why chatgpt not following instructions happens

There are three practical classes of cause: prompt role and wording, account or rate/usage differences, and caching or regeneration bugs. Prompt role problems occur when instructions are placed where the model treats them as context rather than binding rules. Account issues manifest as inconsistent behavior between users on the same model. Finally, prompt caching or regeneration bugs can produce lower quality or contradictory outputs even when your prompt is correct.

Step by step fix

  1. Reproduce with a minimal test. Create a tiny, explicit test that isolates the instruction. For example use a short system role and one user request. This removes long context as a variable.
  2. Swap message roles. Send the same instruction as a system message, then as a developer message, then in the user prompt. The difference often shows whether the model respects the role binding.
  3. Use a tiny, deterministic prompt. Example test you can paste into an API call or ChatGPT dev UI:
System: You are a concise assistant. Always answer in two sentences only.
User: Say hello and explain your role in one sentence.
  1. Regenerate and clear cache. Click Regenerate response, or duplicate the conversation and send again. If available, start a new conversation or clear chat history. Some users report different results after these steps.
  2. Try a model fallback. If GPT-6 behaves poorly, test GPT-4 or another model. If the fallback follows the same steps correctly, the problem is model-specific.
  3. Compare across accounts. If the problem is reproducible for some accounts but not others, check usage and team limits, and compare the exact API request payloads. Differences in account-level features or shared usage limits can explain behavior variation.
  4. Capture a minimal reproducible payload. Save the request and full response headers. If you need to file a bug report, this payload is what support will ask for.

Quick tests and what they tell you

  • If the instruction works as a developer message but not as the instructions field, suspect prompt caching or a bug with how that field is handled. The OpenAI thread about cached tokens points this out. See this prompt caching report.
  • If different accounts see different quality, it may be a model rollout, throttling or a shared usage cap. Reports of gpt 6 not following instructions and response quality regression have been posted by multiple users; compare account-level settings and quotas.
  • If regenerating fixes it, the issue is likely transient or cache-related rather than your prompt wording.

Tool specific notes: n8n, Make.com and Zapier

Automations introduce additional layers where instructions can break. Check these common points.

n8n

  • Use the HTTP Request node to send a controlled API test payload. That isolates n8n workflow variations like credential reuse or variable interpolation.
  • If you use JavaScript in the workflow, use the Code node to construct the exact JSON payload. Avoid templated fields that accidentally strip or escape quotes.
  • When a response changes mid-run, retry from the failed node after clearing workflow state. See Automate Naija guides on retry patterns for safe retries.

Make.com (scenarios)

  • Use a single module to run the test payload and log the full request and response. That helps you see if Make.com is altering headers or the body.
  • Temporarily disable other modules in the scenario to remove side effects like data enrichment or character encoding changes.

Zapier

  • Build a minimal Zap with a Webhooks by Zapier action, send the exact JSON and inspect the raw response. Zapier step transformations sometimes change types or truncate long fields.
  • Use separate test Zaps per model and compare outputs. If only one Zap or account shows regression, it is likely account or integration related.

How to stop it happening again

Reduce surface area and add observability so you can find regressions early.

  • Lock critical constraints into explicit system or developer messages rather than buried user text. System and developer messages are intended to be stronger signals than a later user message.
  • Version your prompts. Keep a canonical test in source control or a shared document, and run it after changes or when you notice drift.
  • Log full request and response payloads with timestamps and model identifier. Include model name, temperature and max tokens fields so differences are visible.
  • Automate regeneration checks. If a single response fails, have a lightweight watchdog job repeat the request once or twice before escalating. This reduces false positives from transient network or cache issues.
  • Track account usage and shared usage limits. If your team hits a quota, behavior can change. See our team playbook on shared usage limits for immediate steps to reduce impact.

When to get help

If you have a minimal reproducible test that fails consistently and the same payload behaves differently across accounts or model versions, escalate. Capture the exact JSON, response headers and timestamps, then open a support ticket with OpenAI and attach your test. Link to community reports such as the OpenAI thread reporting GPT-6 ignoring instructions and the caching report linked above. Support will want the request id or logs to trace model-side behavior.

Immediate mitigations you can do while waiting for help: use a model fallback, duplicate the conversation and resend, or move critical constraints into a developer message. These often restore expected behavior in minutes.

Frequently asked questions

Why does ChatGPT suddenly ignore rules I set in the prompt?

The model may be treating your text as conversational context rather than an enforceable instruction, or there may be account or caching differences. Test by placing the same text as a system or developer message and by regenerating the response. If behavior differs across accounts, check usage limits and file a reproducible test with support.

How do I test whether it is a prompt issue or a model bug?

Create a minimal reproducible prompt and send it in three roles: system, developer, and user. If only one role succeeds, it points to how the prompt is interpreted. If the same payload gives different answers after regenerating, or across accounts, suspect caching or a model-side regression and capture logs for support.

What quick steps should I try inside n8n or Zapier when ChatGPT ignores instructions?

Run a single-step test using the HTTP Request node in n8n or a Webhooks action in Zapier to send the exact JSON. Use the n8n Code node to avoid accidental template interpolation. Compare raw responses, and retry with model fallback or regenerate before changing workflow logic.

When should I open an OpenAI support ticket?

Open a ticket when you have a minimal reproducible payload that fails consistently, or when behavior differs between accounts or models. Include the full request JSON, response headers, timestamps and any request ids. Link to community reports if relevant, and explain what role placement and regeneration tests you already tried.
