Phone number verification not working: quick recovery playbook

Follow this concise troubleshooting playbook to fix phone number verification not working on OpenAI, with every proven cause and exact recovery steps to get past SMS or voice code failures.

By the Automate Naija team·19 November 2026·6 min read

If your phone number verification not working for OpenAI, start by checking number format, VoIP restrictions, device settings and VPNs, then try SMS versus voice, a different carrier or a landline. If those fail, collect timestamps and error text, then escalate to OpenAI support with a short, structured report.

Why this happens

Phone verification can fail for a small set of reliable reasons: carrier blocking of short codes, virtual or VoIP numbers being rejected, country or account location flags, browser or device problems, and temporary service outages. OpenAI and many providers restrict numbers that are known virtual providers, or show suspicious reuse across many accounts, so a number can be rejected at input or never receive codes.

phone number verification not working: step-by-step fix

  1. Confirm formatting and country code. Enter the number in E.164 format: include the plus sign and country code, for example +2348123456789. Do not add extra zeros or local trunk prefixes.
  2. Try SMS and then voice. If SMS does not arrive, request the voice/code by call option. Some carriers block short code SMS but allow voice calls to landlines or mobile.
  3. Test a different SIM or number. Use a different mobile number from a different carrier, or try a trusted family member's number. Avoid Google Voice, Twilio, TextNow, VOIP services and many virtual SIM providers because they are commonly rejected.
  4. Disable VPN and proxies. Turn off any VPN, proxy or private DNS in your device or browser. Location mismatches can trigger automated blocks or additional verification steps.
  5. Check device and messaging settings. Disable Do Not Disturb, message filtering, and any SMS blocking apps. On Android, check Messages app permissions and ensure the carrier service app is updated. On iPhone, check Settings, Messages and Blocked Contacts.
  6. Try another browser or incognito mode. Use a fresh browser session, for example Chrome incognito, or try a different browser. Clear cookies and site data for platform.openai.com or the OpenAI signup page and retry.
  7. Wait and retry later. If you see a server error, or no delivery after several tries, wait 30 to 60 minutes. Carrier routing or short code throttles sometimes recover. Note exact times for escalation if needed.
  8. Collect diagnostics before escalating. Record: the phone number used in E.164 format, approximate timestamps of attempts in UTC, whether you requested SMS or voice, device type and browser, and any on-screen error text such as Number rejected or SMS not received.

Tool specific notes for n8n, Make.com and Zapier

If you are a builder or freelancer using OpenAI within automations, phone verification problems can block API access or new account creation. Here are practical pointers per tool.

  • n8n: If your OpenAI account is unverified API calls from the workflow will fail. Use the HTTP Request node to test endpoints after you regain access. For debugging add a preceding Code node to log environment values and headers before the request. If you hit limits after repeated retries, follow the retry pattern in our post on N8n error handling workflow pattern.
  • Make.com: When testing scenarios, use a single testing account and verify the account first. If you receive authentication errors, check the module settings and use an HTTP module to inspect raw responses. Keep test phone verification attempts to avoid flagging the account.
  • Zapier: Zaps that create new OpenAI resources or accounts will fail if verification is incomplete. Pause Zaps during troubleshooting, and store diagnostic outputs in a Google Sheet step so you can attach samples to support requests.

How to stop it happening again

  • Use a primary mobile number issued by your local major carrier rather than VoIP services.
  • Add a second trusted number to your account when possible, for backup verification.
  • Avoid rapidly creating or deleting accounts from the same number, that pattern triggers automated blocks.
  • Keep browser cookies for the account site intact during verification, and avoid switching networks mid flow.
  • Document phone and carrier details for client accounts so a different known-good number is available when needed.

When to get help and how to escalate to OpenAI support

If you have tried the steps above and the phone number verification issue persists, prepare a concise support ticket. Include the E.164 formatted number, timestamps, your IP location, device and browser, whether you tried SMS or voice, and screenshots. If the interface shows text like Number rejected or a numeric error code, copy it exactly.

OpenAI community threads show other developers reporting the same symptoms. See reports such as Phone number verification not working no matter what number I use and Unable to verify codex using mobile numbers for real examples and to confirm if the issue is widespread at the moment.

Use this support message template and paste it into OpenAI Help or the contact form. Replace placeholders.

Account email: you@example.com
Phone used: +2348123456789
Attempts: 2026-11-19T09:23:00Z (SMS), 2026-11-19T09:35:00Z (voice)
Device and browser: Android 13, Chrome 120 incognito
Error or message seen: "Number rejected" or no SMS received
Steps tried: formatting, different SIM, disabled VPN, incognito, different browser
Request: Please check verification routing or manual verification steps

If you do not hear back in 48 hours, reply with the original ticket number and add a screenshot. For urgent business needs consider asking a colleague with a different carrier to verify for you then transfer API keys securely.

Finally, if your automation or business depends on a stable OpenAI account, keep a verified backup account or team seat, and document verified phone numbers for each client account so you can recover quickly.

Frequently asked questions

Why am I not receiving OpenAI verification SMS?

SMS failures are usually carrier level. Check that the number is in E.164 format with the correct country code, disable VPNs, and verify the carrier does not block short code messages. Try the voice option or a different mobile from another carrier to confirm if it is a carrier routing problem.

Can I use Google Voice or a virtual number for verification?

Most providers including OpenAI often block VoIP and virtual numbers because they are reused across accounts. If your number is virtual, use a physical SIM from a major local carrier or a landline for the voice option instead.

What if the site says the number is rejected when I enter it?

If the UI rejects the number immediately, it likely matches a known blocked range or format. Try a different carrier number, ensure correct E.164 formatting with a plus sign, and do not include local trunk prefixes. Collect the rejection text and escalate to OpenAI support if needed.

What information should I include when contacting OpenAI support?

Provide the account email, the phone number in E.164, UTC timestamps of verification attempts, device and browser used, whether you chose SMS or voice, and screenshots of any on-screen error messages. This speeds up diagnosis and possible manual verification.
