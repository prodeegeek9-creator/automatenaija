ChatGPT desktop app crash on launch Mac, quick recovery

Step by step Mac-first recovery to capture crash logs, clear the corrupt local cache without losing cookies or history, reinstall, and fall back to the web app.

By the Automate Naija team·21 November 2026·6 min read

If the ChatGPT desktop app crashes on launch on your Mac after a recent update, you can recover without losing cookies and history by collecting macOS crash logs, moving only the cache and GPU cache that often corrupt, reinstalling the app cleanly, and switching temporarily to chat.openai.com. Follow this playbook to capture evidence, test fixes, and resume work quickly.

Why this happens and what to capture first

Many reports link a recent update to a corrupted Electron or Chromium cached state inside the app profile, which causes a crash on startup. That is why the app window does not open, or it opens then immediately exits. Before you delete anything, capture logs and the crash report so you can diagnose, report to OpenAI and restore only the broken files.

  • Collect system crash reports from ~/Library/Logs/DiagnosticReports.
  • Collect Console logs with the log utility to see the process crash reason.

Use the forum thread where others report the same crash to add your logs when contacting support: OpenAI dev forum: crash on launch.

chatgpt desktop app crash on launch mac: step by step recovery

  1. Quit the app and prepare a backup folder on the Desktop. 
    mkdir -p ~/Desktop/ChatGPT-recovery-$(date +%Y%m%d-%H%M)
  2. Save the latest DiagnosticReport and Console output. 
    ls -lt ~/Library/Logs/DiagnosticReports | grep ChatGPT | head -n 5
log show --predicate 'process == "ChatGPT"' --last 1h > ~/Desktop/ChatGPT-recovery/log-console.txt
    If you see many entries, increase the time window to 24h with --last 24h.
  3. Inspect the app bundle and move the likely corrupt cache while preserving cookies and history.

    Open the profile folder and list files so you know what will be moved.

    cd ~/Library/Application\ Support/ChatGPT
ls -la
    Common items to keep are files named Cookies and History inside a Default or profile folder. Move caches not these files.
  4. Move cache directories, not SQLite files. This removes the corrupted binary cache while keeping cookies, bookmarks, and history. 
    mkdir -p ~/Desktop/ChatGPT-recovery/Cache-backup
mv "~/Library/Application Support/ChatGPT/Cache" ~/Desktop/ChatGPT-recovery/Cache-backup/ 2>/dev/null || true
mv "~/Library/Application Support/ChatGPT/GPUCache" ~/Desktop/ChatGPT-recovery/Cache-backup/ 2>/dev/null || true
mv "~/Library/Application Support/ChatGPT/Code Cache" ~/Desktop/ChatGPT-recovery/Cache-backup/ 2>/dev/null || true
mv "~/Library/Application Support/ChatGPT/Default/Cache" ~/Desktop/ChatGPT-recovery/Cache-backup/ 2>/dev/null || true
  5. Try launching the app. If it still crashes, preserve your profile files (Cookies, History, Bookmarks, Local Storage) and reinstall.
  6. Uninstall and reinstall safely. 
    rm -rf /Applications/ChatGPT.app
open 'https://chat.openai.com/desktop'
    Download the official installer from OpenAI and install. After reinstall, test if the app opens. If it does, it will reuse the profile in ~/Library/Application Support/ChatGPT.
  7. If reinstall does not fix it, restore profile files one by one. Start with a clean app directory and copy back Cookies and History only, then launch. If it crashes, stop and report logs to support.

How to capture reproducible checks most guides miss

  • Record the process exit code and the system log around the crash moment. 
    log show --predicate 'process == "ChatGPT"' --last 5m --info
ps aux | grep ChatGPT
  • List the profile content before moving anything so you can prove you preserved cookies and history. 
    find "~/Library/Application Support/ChatGPT" -maxdepth 2 -type f -printf "%f\n" | sort
    This shows files like Cookies, History, and database files.
  • If you need to, attach the DiagnosticReport and the log output when posting to the forum or to support. The thread above helps others correlate symptoms: browser extensions and saved passwords thread.

Temporary migration: use the web app and your automations

If the desktop app is unusable, switch to chat.openai.com to continue work immediately. For automations that called the desktop app or used the built in browser, switch to API or the web interface:

  • n8n: use the HTTP Request node to call the OpenAI API, keep your workspace running. Avoid the Code node for HTTP requests. Example, set method POST and the URL to the OpenAI chat completions endpoint, add an Authorization: Bearer YOUR_KEY header, and a JSON body.
  • Make.com: switch any scenario steps that relied on the desktop to the OpenAI module or an HTTP call to the API temporarily.
  • Zapier: use the OpenAI app step or the Webhooks by Zapier step to send prompts while the desktop app is down.

How to stop it happening again

  • Before updating, export or backup ~/Library/Application Support/ChatGPT to an external folder or Time Machine.
  • Keep automatic backups of browser profile files such as Cookies and History.
  • If you run automations in n8n, Make.com or Zapier that depend on the desktop app, design them to use the OpenAI API as a primary path and the desktop as optional UI. See Automate Naija posts on error handling patterns for n8n workflows if you need to switch quickly: N8n error handling workflow pattern.

When to get help and what to include

Contact OpenAI support if after moving caches and reinstalling the app it still crashes. Include the DiagnosticReport from ~/Library/Logs/DiagnosticReports, the output of your log show run, timestamps, macOS version, and a short list of files in the profile you preserved. That gives engineers the best chance to reproduce and fix the bug that caused the chatgpt mac crash or chatgpt app crash mac after update.

Frequently asked questions

How do I find the ChatGPT crash report on my Mac?

Open Finder and go to ~/Library/Logs/DiagnosticReports, then look for files named with ChatGPT and .crash or .diag. You can also use Terminal: run ls -lt ~/Library/Logs/DiagnosticReports | grep ChatGPT to list recent reports, and open the latest with a text editor.

Will moving cache files lose my ChatGPT conversations or passwords?

No, if you only move cache folders like Cache and GPUCache you will not remove SQLite files named Cookies, History or Bookmarks. Those files store passwords and history. Always list files in the profile first and move only the cache directories to a backup folder.

If reinstalling fails, can I still use my conversations?

Yes, switch to the web app at chat.OpenAI.com, sign in and continue work. If conversations were only stored locally and not synced, try to recover the SQLite files from your profile backup. If those files are damaged, report the DiagnosticReport when contacting support.

What quick change should I make in my automations to avoid this outage?

Switch automations to use the OpenAI API as the primary path. In n8n use the HTTP Request node with your API key, in Make.com use the OpenAI module or HTTP step, and in Zapier use the OpenAI or Webhooks step. This decouples automation from the desktop app and avoids disruption when the app crashes.
